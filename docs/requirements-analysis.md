本文档旨在全面、清晰地定义 **KnowFlow（智能学习助手平台）** 的需求范围、功能规格和约束条件，为后续的概要设计、详细设计、编码实现及测试验收提供统一依据。

### 1.3 术语表

| 术语 | 说明 |
|:---|:---|
| **RAG** | Retrieval-Augmented Generation，检索增强生成——将外部知识库检索结果注入 LLM 上下文以提升回答准确性 |
| **ReAct Agent** | Reasoning + Acting 智能体模式，让 AI 自主思考、规划、调用工具并执行多步骤任务 |
| **LLM** | Large Language Model，大语言模型 |
| **Embedding** | 嵌入向量——将文本转换为高维向量表示，用于语义相似度计算 |
| **pgvector** | PostgreSQL 的向量检索扩展，支持 KNN/ANN 近似最近邻搜索 |
| **SSE** | Server-Sent Events，服务器推送事件——实现流式输出的 Web 标准协议 |
| **Tool Calling** | 工具调用——LLM 在生成过程中动态调用外部函数/API 的能力 |
| **Vector Store** | 向量数据库/存储，用于存储和检索 Embedding 向量 |

## 2. 项目背景与目标

### 2.1 行业背景

在 AI 技术飞速发展的当下，程序员和计算机专业学生在自学编程过程中面临三大核心痛点：

1. **即时答疑难** —— 遇到 Bug 或概念不通时，搜索引擎结果碎片化，Stack Overflow 回答质量参差不齐，缺少能「理解上下文」的实时辅导。
2. **资料整理乱** —— 收藏了大量教程、PDF 文档、博客链接，但检索困难，无法快速从自有资料中定位答案。
3. **缺乏模拟面试** —— 求职准备阶段缺少针对性的虚拟面试和代码评审环境。

### 2.2 项目目标

构建一个基于 **Spring AI 2.0** 官方框架与 **RAG（检索增强生成）** 技术的全栈智能学习助手平台，实现以下核心目标：

- **G1**：提供上下文感知的多轮 AI 对话，充当"24 小时编程导师"。
- **G2**：支持用户上传自有学习资料（PDF/Markdown），AI 基于私有知识库精准回答。
- **G3**：AI 能自主调用外部工具（如搜索引擎、代码执行器）完成复杂多步骤任务。
- **G4**：提供流畅的流式交互体验，逐字展示 AI 思考过程。
- **G5**：保障用户数据安全与隐私，支持多用户隔离。

### 2.3 成功标准

| 指标 | 目标值 |
|:---|:---|
| 对话响应首字节时间（TTFB） | ≤ 1.5s |
| 文档解析成功率 | ≥ 98% |
| RAG 答案相关性满意度 | ≥ 85% |
| 系统可用性（正常运行时间） | ≥ 99.5% |
| 单用户并发对话数 | ≥ 5 |

### 4.2 用户管理模块

#### UC-01 用户注册

| 项目 | 内容 |
|:---|:---|
| **用例名称** | 用户注册 |
| **优先级** | P0（高） |
| **前置条件** | 无 |
| **后置条件** | 系统创建新用户，返回 JWT Token |
| **基本流程** | 1. 用户输入用户名和密码 → 2. 系统校验用户名唯一性 → 3. 密码加密存储 → 4. 生成 Token 并返回 |
| **备选流程** | 用户名已存在：返回 409 错误提示 |
| **验收标准** | ✅ 注册成功后自动登录并跳转聊天页 ✅ 用户名重复时有明确错误提示 |

#### UC-02 用户登录

| 项目 | 内容 |
|:---|:---|
| **用例名称** | 用户登录 |
| **优先级** | P0（高） |
| **前置条件** | 用户已注册 |
| **基本流程** | 1. 输入用户名/密码 → 2. 校验凭据 → 3. 生成 JWT Token → 4. 返回用户信息 + Token |
| **验收标准** | ✅ Token 存储在 localStorage ✅ 未登录访问受保护路由自动跳转登录页 |

### 4.4 RAG 知识库模块

#### UC-05 文档上传与解析

| 项目 | 内容 |
|:---|:---|
| **用例名称** | 文档上传与解析 |
| **优先级** | P0（高） |
| **前置条件** | 用户已登录，处于知识库页面 |
| **基本流程** | 1. 点击"上传文档"按钮 → 2. 选择 PDF 或 Markdown 文件 → 3. 系统使用 Apache Tika 解析文档内容 → 4. 文本分块（Chunking）→ 5. 调用 Embedding API 生成向量 → 6. 存储到 pgvector |
| **注意事项** | 文件大小限制（建议 ≤ 20MB）、支持格式白名单 |
| **验收标准** | ✅ 上传后显示"处理中"状态 ✅ 处理完成状态变为"已就绪" ✅ 解析失败则标记为"失败"并有错误信息 |

#### UC-06 基于知识库的精准问答

| 项目 | 内容 |
|:---|:---|
| **用例名称** | 基于知识库的精准问答 |
| **优先级** | P0（高） |
| **前置条件** | 用户已上传至少一份文档且状态为"已就绪" |
| **基本流程** | 1. 用户在对话中输入问题 → 2. 系统将问题转为 Embedding 向量 → 3. 在 pgvector 中执行相似度搜索（ANN）→ 4. 检索 Top-K 相关片段 → 5. 将片段注入 Prompt 上下文 → 6. LLM 基于上下文生成答案 |
| **核心技术** | `PgVectorStore` + `QuestionAnswerAdvisor` |
| **验收标准** | ✅ 答案引用知识库内容且准确 ✅ 无明显幻觉（编造不存在的资料内容） |

### 4.5 Tool Calling 模块

| 项目 | 内容 |
|:---|:---|
| **用例名称** | 智能工具调用 |

### 6.2 架构核心决策

| 决策 | 选择 | 理由 |
|:---|:---|:---|
| 后端单体 vs 微服务 | **多模块单体** | 项目初期规模小，单体架构开发效率最高；模块化分包便于未来拆分微服务 |
| AI 框架 | **Spring AI 2.0** | 官方最新版，原生支持 RAG/ReAct/Tool Calling，Java 生态集成最佳 |
| 向量数据库 | **pgvector** | 与业务数据同库管理，无需额外运维一套专用向量数据库 |
| 前端状态管理 | **Pinia** | Vue 3 官方推荐，TypeScript 支持优秀，API 简洁 |
| UI 组件库 | **TDesign** | 腾讯企业级设计体系，组件丰富，视觉专业度高 |

### 6.3 数据流说明

#### 6.3.1 RAG 问答数据流

```
用户提问
   │
   ▼
① 问题 Embedding 化 ──→ ② pgvector ANN 搜索
                                │
                                ▼
                      ③ 返回 Top-K 相关片段
                                │
                                ▼
                      ④ 注入 Prompt 上下文
                                │
                                ▼
                      ⑤ LLM 生成回答 ──→ ⑥ SSE 流式返回
```

#### 6.3.2 文档上传数据流

```
用户上传文件
   │
   ▼
① Apache Tika 解析文本
   │
   ▼
② 文本分块（Chunking）
   │
   ▼
③ 每块调用 Embedding API 生成向量
   │
   ▼
④ 向量 + 元数据存入 pgvector
   │
   ▼
⑤ 更新文档状态为"已就绪"
```

#### 6.3.3 ReAct Agent 工作流

```
用户复杂任务指令
   │
   ▼
① AI 分析任务 → 拆解子步骤
   │
   ▼
② 选择工具（搜索/代码执行/知识库查询）
   │
   ▼
③ 执行工具 → 获取结果
   │
   ▼
④ 评估结果 → 是否完成任务？
   ├── 是 → 汇总输出最终答案
   └── 否 → 回到步骤②继续循环
```

### 8.4 SSE 协议规范

```
GET /api/chat/stream?conversationId=1
Authorization: Bearer <token>
Accept: text/event-stream

响应：
event: token
data: {"content": "好的"}

event: token
data: {"content": "，我来"}

event: token
data: {"content": "帮你分析..."}

event: done
data: {"conversationId": 1}

event: error
data: {"message": "服务暂时不可用"}
```

| 事件名 | 说明 | 数据字段 |
|:---|:---|:---|
| `token` | AI 输出片段 | `{ content: string }` |
| `done` | 回复结束 | `{ conversationId: number }` |
| `error` | 错误信息 | `{ message: string }` |
